Section 0.1.1 • Day-1 Security Mental Model

1. Thinking in Invariants & Trust Boundaries

In university programming, you mostly ask: "Does my code work for normal inputs?" In cybersecurity engineering, you ask a completely different question: "What hidden assumption (invariant) did the programmer rely on—and what untrusted input breaks it?"

  • Trust Boundary: Any edge where untrusted external bytes (network packet, file, HTTP body, CLI argument, game client packet) cross into trusted logic (allocator, database, kernel, access check).
  • Broken Invariant Example: In ordinary math, x + 16 > x is always true. On a 32-bit unsigned CPU register, if x = 0xFFFFFFF8, then x + 16 == 8! The programmer's math assumption breaks, and a buffer overflow is born.
Section 0.1.2 • Speaking the Machine's Native Language

2. Binary, Hexadecimal & Bitwise Operations

Security engineers read Hexadecimal (0x) fluently because 1 hex digit maps to exactly 4 bits (1 nibble), and 2 hex digits equal 1 byte (8 bits: 0x00 to 0xFF).

Operator Meaning Real Security / Systems Use
& (AND) Keep only selected bits (masking) Check TCP flags (flags & 0x02 = SYN), check permission bits, page alignment (addr & ~0xFFF)
| (OR) Turn specific bits ON Combine Linux open() flags (O_CREAT | O_WRONLY) or chmod bits
^ (XOR) Toggle bits / self-inverse (A ^ K ^ K = A) Stream ciphers, one-time pad, malware obfuscation, zeroing CPU registers (xor eax, eax)
<< / >> Shift left (×2) / right (÷2) Bit-packing headers; Watch out: right-shifting a negative signed integer performs sign extension (arithmetic shift), keeping the MSB 1!
Section 0.1.3 • Classic C & Game/Systems CVEs

3. Two's Complement, Signedness Bugs & Integer Overflows

Computers don't store a separate minus sign. They use Two's Complement so the exact same adder hardware handles both signed and unsigned math. To negate a value in Two's Complement: invert all bits and add 1 (-x == (~x) + 1).

That means the exact same bit pattern 0xFF (11111111) means 255 as uint8_t, and -1 as int8_t! The bits themselves have NO type—the instruction or C type decides how to interpret them.

Figure 1: Fixed-width arithmetic wraps around mod 2^N—turning large positive sizes into tiny buffers or negative numbers.

3 Real-World Integer CVE Patterns Every Engineer Must Recognize

/* Pattern 1: Unsigned Wrap-Around before malloc() */
uint32_t total = user_len + 16;      // If user_len = 0xFFFFFFF8, total wraps to 8!
char *buf = malloc(total);            // Allocates only 8 bytes on the heap!
memcpy(buf, untrusted, user_len);    // Copies ~4 GB into an 8-byte buffer -> HEAP OVERFLOW!

/* Pattern 2: Signed-to-Unsigned Promotion Trap */
int32_t len = read_packet_len();     // Attacker sends -5 (0xFFFFFFFB)
if (len > 1024) return -1;           // -5 > 1024 is FALSE! Upper bound bypassed!
memcpy(dst, src, len);               // 3rd param is size_t (unsigned) -> HUGE copy!

/* Pattern 3: Broken Signed Overflow Check Deleted by Compiler Optimization */
if (a + b < a) { ... }               // WRONG for signed int: UB lets gcc -O2 delete this check!
if (__builtin_add_overflow(a, b, &res)) { reject(); } // SAFE & deterministic!

Section 0.1.5 • Byte Order in RAM vs. Network Packets

5. Endianness: Little-Endian (x86_64/ARM64) vs. Big-Endian (Network)

A single byte has no endianness. Endianness only applies when storing a multi-byte integer (uint16_t, uint32_t, uint64_t, memory addresses) across consecutive memory bytes:

  • Little-Endian (x86_64, ARM64 default): The Least Significant Byte (LSB) sits at the lowest memory address. When inspecting memory in gdb (x/4xb), multi-byte numbers appear "reversed" byte-by-byte!
  • Big-Endian (Network Byte Order — TCP/IP headers): The Most Significant Byte (MSB) sits at the lowest address (human left-to-right reading order). That is why socket code uses htons() / ntohs() / htonl()!
Figure 2: Little-Endian reverses multi-byte integers in RAM, while 1-byte char arrays keep sequential order.
Section 0.1.6 • LangSec & Parser Differentials

6. ASCII, UTF-8, Null-Byte (0x00) Truncation & Encoding Pitfalls

A huge percentage of real vulnerabilities happen when two layers disagree on where a string ends or what characters it contains:

Figure 3: Classic Null-Byte Parser Differential—used in historic file-upload, PHP, and X.509 SSL certificate attacks.
Attacker Lens

Probes input boundaries with negative numbers (-1, INT_MIN), boundary integers (0xFFFFFFFF, 0x7FFFFFFF), embedded \x00 bytes, and non-canonical UTF-8 / Unicode homoglyphs (e.g., overlong %c0%af for /) to split what the validator sees from what the backend executes.

Defender Lens

Enforces invariants at the trust boundary: use unsigned/fixed-width types (uint32_t, size_t) with checked arithmetic (__builtin_mul_overflow), explicitly reject negative values before casting, reject embedded NUL bytes (memchr(buf, '\0', len)), and canonicalize strings before validating.
